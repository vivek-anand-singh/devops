## The Story of Git and GitHub — The Code Odyssey

### Chapter 1: The Chaos Before Version Control

- Developers shared files over email → version chaos (e.g. `app_final_v3_really_final_final.py`)
- Fixes overwrote each other; no single source of truth
- **Solution:** Version Control — track every change to code, forever

### Chapter 2: What is SCM?

**SCM = Source Code Management** — helps teams collaborate on code safely.

| Type             | Where the Code Lives              | Example        |
|------------------|-----------------------------------|----------------|
| **Local SCM**    | Only on your computer             | RCS            |
| **Remote SCM**   | Central server everyone connects to | Subversion (SVN) |
| **Distributed SCM** | Each developer has full copy of history | **Git**    |

- **Git** is distributed: everyone has full history; you can work offline.

### Comparison of Repository Types

| Aspect                | Local | Remote | Distributed (Git) |
|-----------------------|-------|--------|-------------------|
| **Collaboration**     | One user only | Via central server | Full copy per user, full collaboration |
| **Ecosystem**         | Limited | GitHub, GitLab, Bitbucket | Same + offline |
| **Availability**      | Data loss if machine fails | Depends on server | Redundant (every clone = backup) |
| **Network**           | None (local) | Every op needs network | Offline; sync when needed |
| **Summary**           | Isolated | Centralized, network-dependent | Collaboration + offline |

## The Four Areas in Git

| Area              | Also Called     | Description | Example Command |
|-------------------|-----------------|-------------|------------------|
| **Working Tree**  | Workspace       | Files you edit; not yet tracked | `git status` |
| **Staging Area**  | Index / Cache   | Prepare files for next commit | `git add file.txt` |
| **Local Repository** | `.git` directory | Commits, branches, history | `git commit` |
| **Remote Repository** | Origin (often) | Server copy (e.g. GitHub) | `git push` |

**Flow:** Working Tree → `git add` → Staging Area → `git commit` → Local Repo → `git push` → Remote Repo

## Tracking and Committing Files

```bash
touch Abc.txt Xyz.txt
git status                    # Untracked: Abc.txt, Xyz.txt

git add Abc.txt               # stage one file (check .git/objects for new hash)
git status                    # Changes to be committed: Abc.txt; Untracked: Xyz.txt

git commit -m "Learn git commit"
# Till here: all local, no internet needed.
```

## Viewing Status & Differences

| Command | Purpose |
|--------|---------|
| `git status` | Changed files, state of working tree and index |
| `git diff` | Unstaged changes (working tree vs index) |
| `git diff --cached` or `git diff --staged` | Staged changes (index vs last commit) |
| `git diff <commitA> <commitB>` | Diffs between commits/branches/tags |
| `git log` | Commit history (linear) |
| `git log --oneline --graph --decorate --all` | Compact visual commit graph |
| `git show <commit>` | Details and patch for a commit |
| `git blame <file>` | Who/when changed each line |
| `git shortlog -s -n` | Commits summarized by author |

## Staging & Committing

| Command | Purpose |
|--------|---------|
| `git add file.txt` | Stage file (working tree → index) |
| `git add -p` | Interactively stage hunks |
| `git add .` / `git add -A` | Stage all (`.` = CWD tracked; `-A` = all) |
| `git restore --staged file.txt` | Unstage file |
| `git commit -m "message"` | Commit staged changes |
| `git commit --amend` | Amend last commit (message or add staged) |
| `git commit -v` | Show diff in editor when composing message |
| `git commit --allow-empty -m "msg"` | Empty commit (e.g. for CI trigger) |

## Branching & Switching

- **Ref:** https://www.freecodecamp.org/news/git-branching-commands-explained/

| Command | Purpose |
|--------|---------|
| `git branch` | List local branches |
| `git branch -a` | List all (local + remote) |
| `git branch feature/x` | Create branch (no switch) |
| `git checkout feature/x` | Switch (legacy) |
| `git switch feature/x` | Switch (modern) |
| `git switch -c feature/y` | Create and switch to new branch |
| `git branch -d feature/old` | Delete branch (if merged) |
| `git branch -D feature/old` | Force-delete branch |
| `git merge feature/x` | Merge into current (merge commit by default) |
| `git merge --no-ff feature/x` | Force merge commit |
| `git rebase master` | Rebase current onto master |
| `git rebase -i HEAD~5` | Interactive rebase (squash, reorder, edit) |
| `git rebase --abort` / `git rebase --continue` | Abort or continue rebase |

## Remote Repositories

| Command | Purpose |
|--------|---------|
| `git remote -v` | Show remotes and URLs |
| `git remote add origin git@github.com:user/repo.git` | Add remote `origin` |
| `git fetch origin` | Fetch updates (no merge) |
| `git pull` | Fetch + merge |
| `git pull --rebase` | Fetch and rebase local onto fetched |
| `git push origin feature/x` | Push branch |
| `git push -u origin feature/x` | Push and set upstream |
| `git push --force-with-lease origin feature/x` | Safe force-push |
| `git push --tags` | Push tags |
| `git remote set-url origin <new-url>` | Change remote URL |
| `git ls-remote origin` | Show remote refs without fetch |

## Stashing

| Command | Purpose |
|--------|---------|
| `git stash` | Stash uncommitted changes |
| `git stash push -m "WIP: experiment"` | Stash with message |
| `git stash list` | List stashes |
| `git stash show -p stash@{0}` | Show diff of stash |
| `git stash apply stash@{0}` | Reapply, keep in list |
| `git stash pop` | Reapply and remove from list |
| `git stash drop stash@{0}` / `git stash clear` | Remove one / clear all |

## Undoing & History (use carefully)

| Command | Purpose |
|--------|---------|
| `git revert <commit>` | New commit that undoes `<commit>` (safe) |
| `git reset --soft HEAD~1` | Move HEAD back, keep changes staged |
| `git reset --mixed HEAD~1` | Move HEAD back, unstage (keep working tree) |
| `git reset --hard HEAD~1` | Move HEAD back, discard changes (destructive) |
| `git reflog` | History of HEAD (recover lost commits) |
| `git cherry-pick <commit>` | Apply one commit onto current branch |
| `git filter-branch --tree-filter 'rm -rf secret' HEAD` | Rewrite history (prefer `git filter-repo` if available) |

## Example Workflows

**Feature branch:**
```bash
git checkout -b feature/awesome
# make changes
git add .
git commit -m "Implement awesome feature"
git push -u origin feature/awesome
# open PR on remote
```

**Rebase before merge:**
```bash
git checkout feature/awesome
git fetch origin
git rebase origin/main
# resolve conflicts
git push --force-with-lease origin feature/awesome
```

**Merge to main:**
```bash
git checkout main
git pull origin main
git merge --no-ff feature/awesome
git push origin main
```

**Squash then push:**
```bash
git checkout feature/awesome
git rebase -i origin/main
# squash in editor
git push --force-with-lease
```
